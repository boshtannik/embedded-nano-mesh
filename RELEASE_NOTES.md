# Release notes — embedded-nano-mesh 3.0.0

## Summary

This is a **breaking release** that removes the blocking high-level methods
(`send_ping_pong`, `send_with_transaction`) from the library core. The protocol
becomes a pure non-blocking transport: sending never stalls the user program loop.

The **wire format is unchanged**, so v3 nodes are fully interoperable with v2
nodes in the same network. This was verified with a new cross-version test suite.

## Breaking changes

- Removed `send_ping_pong()` — no more blocking wait-for-response.
- Removed `send_with_transaction()` — no more 4-step guaranteed delivery.
- Removed `PacketState`, `StateMutator`, `SpecialSendError` and all related
  ping/pong + transaction bit flags.
- Delivery guarantees (ack, retry, transactions) are now the **application
  layer's responsibility**. Build them on top of `send_to_exact` / `broadcast` /
  `receive` if you need them.

## What's new

- Fully non-blocking API: `Node::new`, `send_to_exact`, `broadcast`, `receive`,
  `update`.
- `Packet::get_lifetime()` getter for remaining TTL.
- Unit tests for the router (receive / transit / broadcast cases) and packet
  serialization round-trip + checksum.
- Cross-version compatibility tests: v3 nodes interoperate with v2.1.11 nodes
  (send_to_exact, broadcast, 2-hop transit, ping-pong through a v3 relay) in
  the same simulated ether. The matrix is generated by
  `tests/test_version_compatibility.rs` and mirrored in the README.
- Full public API documentation (no `missing_docs` warnings).
- Duplicate filter is now compile-time configurable via environment variables
  or a `.env` file (see `.env.example`): ignore period, table size, and
  overflow strategy. The default `evict_oldest` strategy drops the oldest
  entry when the table is full instead of silently rejecting new packets.
- License is now SPDX `MIT OR Apache-2.0 OR GPL-3.0-or-later` — pick whatever
  fits your project.

## Compatibility

| Scenario | Topology | Status |
|----------|----------|:------:|
| send_to_exact | v3 -> v2 | pass |
| send_to_exact | v2 -> v3 | pass |
| broadcast | v3 -> v2 | pass |
| broadcast | v2 -> v3 | pass |
| send_to_exact through relay | v3 -> v2 -> v3 | pass |
| ping-pong through relay | v2 -> v3 -> v2 | pass |
| transaction through relay | v2 -> v3 -> v2 | fail |

Mixed networks (some nodes on v2, some on v3) keep working for the transport
methods above.

Known limitation: a v2 `send_with_transaction` cannot complete when the
transaction packets must transit through a v3 relay node — the v3 duplicate
filter drops the `FinishTransaction` step because it reuses the unique id of
`AcceptTransaction`. Ping-pong and plain packet forwarding are unaffected.

## Migration guide (v2 → v3)

Replace:

```rust
// v2: blocking wait for a reply
mesh_node.send_ping_pong(data, dest, lifetime, filter, timeout);
```

with:

```rust
// v3: send and handle the reply yourself in the main loop
mesh_node.send_to_exact(data, dest, lifetime, filter);
// ... later, in the loop ...
if let Some(reply) = mesh_node.receive() { /* handle */ }
```
